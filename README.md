# AS-APP Mobile

Мобильное приложение AS Group для управления строительством: offline-first B2B
клиент на Expo (React Native) + WatermelonDB + Supabase.

## Возможности
- **Offline-first**: все данные сначала пишутся локально (WatermelonDB — SQLite на
  устройстве, LokiJS в web), затем синхронизируются.
- **Двусторонняя синхронизация** с Supabase (pull/push, порядок таблиц с учётом FK).
- **Модель строительства**: объекты, проекты, сметы, договоры, задания, отчёты.
- **Закупки и склад**: заявки, заказы, входящий контроль и приёмка ТМЦ.
- **Документы и ЭЦП**: согласование и подписание актов.
- **Отчёты с подтверждением**: фото с камеры + геолокация объекта.
- **Мультисерверность**: выбор сервера из списка или по QR-коду.

## Фирменный стиль
Единственный источник правды по цвету, типографике и отступам —
[`src/theme/index.ts`](src/theme/index.ts). Палитра построена на фирменных
цветах AS Group:

Тема **светлая**: приложением пользуются на площадке при прямом солнце, где
светлый фон с тёмным текстом читается заметно лучше тёмного.

| Токен | Значение | Назначение |
|---|---|---|
| `brand` / `primary` | `#00387E` | Корпоративный синий: кнопки, иконки, активный таб (контраст на белом ~11:1) |
| `accentFill` | `#FFA100` | Корпоративный янтарный для заливок и индикаторов |
| `accent` | `#A05F00` | Тот же янтарный для ТЕКСТА: `#FFA100` на белом даёт ~1.9:1 и нечитаем |
| `canvas` / `surface` | `#F4F6FA` / `#FFFFFF` | Фон приложения и карточки |

Семантические цвета (`success`, `warning`, `danger`, `info`) используются и как
текст, и как заливка, поэтому подобраны «текстобезопасными» — контраст ≥ 4.5:1
на белом. Для ярких плашек есть парные `*Fill`.

Логотип отрисован кодом (`src/components/Brand.tsx`), а не картинкой —
`BrandMark`, `BrandWordmark`, `BrandLockup`. Значения цветов дублируются в
`tailwind.config.js` для NativeWind: правки нужно вносить в оба файла.

Иконки — `@expo/vector-icons` (MaterialCommunityIcons) через обёртку
`src/components/Icon.tsx`. Эмодзи в роли иконок не используются: они рисуются
системным шрифтом, выглядят по-разному на iOS и Android и не наследуют цвет.

Общие элементы интерфейса — `src/components/ui.tsx`: `ScreenHeader`, `Card`,
`Badge`, `StatTile`, `Segmented`, `ListRow`, `EmptyState`, `Field`, `TextField`,
`Choice`, `PrimaryButton`, `Fab`, `InfoRow`. Новые экраны собираются из них.

## Требования
- Node.js 20+
- Xcode / Android Studio для нативных сборок (или Expo Go для быстрой проверки)
- Проект Supabase

## Установка
```bash
npm install
cp .env.example .env   # заполнить своими значениями
```

Переменные окружения (`.env`, файл не коммитится):

| Переменная | Назначение |
|---|---|
| `EXPO_PUBLIC_SUPABASE_URL` | URL проекта Supabase по умолчанию |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Anon-ключ Supabase |
| `EXPO_PUBLIC_SIGN_SERVICE_URL` | Сервис подписания ЭЦП. Без него кнопка «Подписать ЭЦП» отключена: приложение не отправит закрытый ключ на неизвестный хост |

## Разработка
```bash
npx expo start          # Expo Go / dev client
npm run ios             # нативная сборка iOS
npm run android         # нативная сборка Android
npx tsc --noEmit        # проверка типов
```

Нативные папки `ios/` и `android/` генерируемые и в git не хранятся. После
изменения `app.json` (имя, bundle id, иконки) их нужно перегенерировать:

```bash
npx expo prebuild --clean
```

## Структура
- `src/theme` — дизайн-система (цвет, типографика, отступы, тени).
- `src/components` — UI-кит, иконки, фирменный знак, выбор объекта.
- `src/lib/domain.ts` — коды, подписи и цвета статусов предметной области.
- `src/database` — схема WatermelonDB, миграции, модели и логика синхронизации.
- `src/screens/auth` — вход, регистрация, онбординг, настройка сервера.
- `src/screens/app` — рабочие экраны: проекты, задания, закупки, склад, документы.
- `src/store` — состояние (Zustand): авторизация и конфигурация сервера.
- `sql/` — схемы и миграции Supabase.

## Разделы приложения

Информационная архитектура отражает предметную область, а не историю
разработки. Пять вкладок:

| Вкладка | Содержимое |
|---|---|
| **Объекты** | Сводка, требующие внимания предписания, быстрые действия, список объектов |
| **Работы** | Задания по сметам и ГПР, внесение оперфакта по объёмам |
| **Ресурсы** | Материалы (склад), техника, оборудование, инструменты |
| **Контроль** | Проверки технадзора, предписания, технические отклонения |
| **Ещё** | Закупки, приёмка, документы, согласование, синхронизация, профиль |

### Учёт ресурсов
- **Материалы** — количественный учёт через журнал движений (приход, выдача в
  работу, списание, возврат, перемещение, инвентаризация). Остаток не хранится
  отдельной изменяемой строкой, а считается агрегацией журнала: правка одного
  остатка с нескольких устройств офлайн неизбежно расходилась бы.
- **Техника, оборудование, инструменты** — единичный учёт с состоянием
  (в работе / простой / ремонт / списано) и историей движений: выдача,
  возврат, перемещение, ремонт. Для техники дополнительно наработка смен
  в машино-часах.

### Технадзор
- **Проверки** — входной, операционный, приёмочный контроль и освидетельствование
  скрытых работ. Фиксируются с координатами; при результате «не соответствует»
  приложение предлагает сразу выдать предписание.
- **Предписания** — нарушение, требование, критичность и срок устранения.
  Рабочий цикл: выдано → в работе → предъявлено → проверено/возвращено.
  Просроченные поднимаются в начало списка и на главный экран.
- **Технические отклонения** — отступление от проекта с обоснованием и
  предлагаемым решением, с согласованием технической службой.

Схемы этих разделов: [sql/modules_resources_control.sql](sql/modules_resources_control.sql).
Пока скрипт не выполнен, разделы работают локально — синхронизация помечает их
таблицы необязательными и не падает из-за отсутствия.
